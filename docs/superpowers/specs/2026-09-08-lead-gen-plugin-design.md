# Lead Gen Plugin — Design Spec

Date: 2026-09-08

## Purpose

Claude Code Plugin для двухэтапной генерации B2B-лидов:

1. **ICP Builder** — интервью с пользователем, формирует Ideal Customer Profile.
2. **Deep Research** — оркестратор параллельных агентов ищет реальные компании/контакты под ICP и сохраняет результат в файл.

Источник для Phase 1 — диалог с пользователем (никаких внешних данных). Источники для Phase 2 — Firecrawl-скиллы (firecrawl-lead-gen, firecrawl-company-directories, firecrawl-deep-research и т.д.) плюс встроенные WebSearch/WebFetch как фоллбэк; список может расширяться позже.

## Non-goals

- Не строим отдельный MCP-сервер — Agent tool в Claude Code уже параллелит работу subagent'ов.
- Не заливаем лиды в CRM автоматически (можно добавить отдельной командой позже).
- Не храним историю ICP в базе данных — только файлы в рабочей директории.
- Не делаем UI — весь процесс идёт через диалог и markdown/CSV файлы.

## Structure

```
lead-gen-plugin/
├── .claude-plugin/plugin.json
├── commands/
│   └── lead-gen.md              # входная точка: /lead-gen
└── skills/
    ├── icp-builder/SKILL.md     # Phase 1
    └── deep-research/SKILL.md   # Phase 2
```

`/lead-gen` — единственная команда-вход. Она объясняет пользователю, что сейчас начнётся интервью, и вызывает skill `icp-builder`. По завершении Phase 1 предлагает перейти к `deep-research` (с подтверждением, не автоматически).

## Phase 1 — ICP Builder

Промпт пользователя (Discovery → Delivery) переносится в `skills/icp-builder/SKILL.md` почти без изменений: те же 9 слотов, интервью по 1-2 вопроса за ход с 3-5 предложенными вариантами, чекпоинт с Draft ICP и подтверждением "go".

Единственное изменение относительно исходного промпта: то, что было **Block B** (текстовый Deep Research prompt для стороннего инструмента типа ChatGPT), в плагине не отдаётся пользователю как копипаст-текст. Вместо этого:

- **Block A (ICP Brief)** сохраняется как файл `icp-brief.md` в рабочей директории — структурированный markdown с полями: Offer, Target segment, Firmographics, Geography & language, Decision-maker, Core pain, Buying triggers, Must-have/Nice-to-have criteria, Disqualifiers, Lookalike anchor.
- **Block B (query patterns, источники)** тоже сохраняется, но в структурированном виде внутри того же файла (или отдельной секции) — как вход для оркестратора Phase 2, а не как чужой prompt-текст для копирования.

После сохранения `icp-brief.md` скилл сообщает пользователю, что ICP готов, и спрашивает, запускать ли Phase 2 сейчас.

## Phase 2 — Deep Research оркестратор

`skills/deep-research/SKILL.md` читает `icp-brief.md` и действует как оркестратор:

1. **Уточняет перед стартом** (через AskUserQuestion или прямой вопрос в чате):
   - есть ли платный Firecrawl API-ключ или ориентироваться на бесплатный тир;
   - желаемый объём N компаний (default 30–50, как в исходном промпте).
2. **Формирует каналы поиска** на основе ICP (гео + язык определяют состав): например — бизнес-реестры/каталоги, Google Maps/отзывы, LinkedIn/соцсети, новости/тендеры/триггеры. Количество и состав каналов зависят от ICP, не фиксированы жёстко.
3. **Запускает по одному агенту на канал параллельно** (Agent tool, subagent_type: general-purpose или fork, один вызов с несколькими tool-use блоками — как требует раздел "parallel" в системных инструкциях). Каждый агент получает:
   - критерии ICP (must-have, nice-to-have, disqualifiers, гео, язык);
   - свой канал поиска и рекомендованные query patterns для него;
   - правила скоринга: must-have 60 баллов (компания без хотя бы одного must-have исключается, не скорится), nice-to-have 25 баллов, триггеры за последние 12 месяцев 15 баллов;
   - жёсткое требование: каждый факт — с source URL, реальные действующие компании, никаких догадок.
4. **Сводит результаты**: дедуплицирует компании (по домену/названию), пересчитывает/сверяет score, сортирует по убыванию, обрезает до N, отбрасывает слабые совпадения (лучше меньше подтверждённых, чем больше сомнительных — как в исходном промпте).
5. **Сохраняет вывод**:
   - `leads-<YYYY-MM-DD>.md` — markdown-таблица: `# | Company | Website | Instagram | Facebook | LinkedIn | Google Maps | Score | Triggers (source URL) | Why it fits`, плюс 3-5 строк о том, какие критерии было сложнее всего проверить.
   - опционально `leads-<YYYY-MM-DD>.csv` — та же таблица для импорта куда угодно.

## Error handling / edge cases

- Если `icp-brief.md` не найден при запуске `deep-research` напрямую (без `/lead-gen` → `icp-builder`) — скилл сообщает об этом и предлагает сначала пройти ICP Builder.
- Если агент по каналу не находит ни одной компании — это допустимо, оркестратор не считает это ошибкой, просто у канала пустой вклад в финальную таблицу.
- Firecrawl недоступен / нет ключа — агенты используют WebSearch/WebFetch как фоллбэк, оркестратор предупреждает, что охват может быть уже.

## Testing

Ручная проверка сквозного сценария: `/lead-gen` → пройти интервью → получить `icp-brief.md` → подтвердить запуск Phase 2 → получить `leads-*.md` с непустой таблицей и работающими source URL хотя бы у части строк.
